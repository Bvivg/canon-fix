# Canon MF463dw II / MF460 по USB — общая база проблем и решений (версия 2)

Сводка по трём компьютерам, где чинили печать и сканирование. Для каждой проблемы указано, на каком ПК она встретилась, как её распознать, как её решали и чем она опасна.

> **Важно.** ID устройств, номера `oemXX.inf`, номера USB-портов (`USB003`, `USB006`, `USB008`…), версии драйверов и программ на каждом ПК свои. Команды ниже по возможности сами находят нужные значения, но перед любым изменением проверяйте, что именно они нашли. Серийные номера, IP-адреса и содержимое сканов в базу намеренно не включены.

## 2. Как устроен аппарат

MF463dw II — составное (composite) USB-устройство. У него два интерфейса, и **оба выглядят для Windows как принтер**:

| Интерфейс | Дескриптор | Узел в системе (норма) | Назначение |
|---|---|---|---|
| Interface 0 | `Class_07 SubClass_01 Prot_04` (IPP-USB) | `MI_00`, класс **Image**, служба `usbscan`, драйвер Canon `mfscn.inf` | сканер |
| Interface 1 | `Class_07 SubClass_01 Prot_02` | `MI_01`, класс **USB**, служба `usbprint` | печать |

Над ними стоит родительский узел `USB Composite Device` (служба `usbccgp`). В его Instance ID в норме стоит **серийный номер аппарата** (12 hex-символов).

**Норма — три присутствующих узла `VID_04A9`, все с `problem: 0`:**

```
USB      USB Composite Device         svc=usbccgp   prob=0   ← родитель, по серийнику
Image    Canon MF460 (II) Series      svc=usbscan   prob=0   ← MI_00, сканер
USB      Canon MF460 (II) Series UFR  svc=usbprint  prob=0   ← MI_01, печать
```

**Физически:** кабель к компьютеру подключается в **квадратный разъём USB-B на задней панели** аппарата. Плоский USB-A спереди — для флешек. Рядом с USB-B находится разъём LAN, и USB-штекер в него **влезает** (см. П10).

**Интерфейсы печати в реестре:**
- `{28d78fad-5a12-11d1-ae5b-0000f803a8c2}` — классический интерфейс печати, его использует родной драйвер Canon;
- `{f2f40381-...}` — IPP-over-USB, его использует драйвер Microsoft IPP.

## 3. Главное правило: определяем аппарат по PID

Надпись на корпусе и название в «Программах» не надёжны. Определять только по PID:

```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -match 'VID_04A9&PID_(\w{4})' } |
  ForEach-Object { $Matches[1] } | Select-Object -Unique
```

| PID | Имя в системе | Пакет драйвера сканера (`mfscn.inf`) покрывает | Ветка ScanGear | Программа сканирования |
|---|---|---|---|---|
| `28B5` | Canon MF460 Series | `PID_28B4`, `PID_28B5` | `SateraMFP1` | **MF Scan Utility 1.21** |
| `28DC` | Canon MF460 II Series | `PID_28DB`, `PID_28DC` | `SateraMFP3` | **MF Scan Utility 2 / Canon Scan Utility** |

Программы для одной модели **не работают** с другой. Если на ПК стоят программы от обеих моделей (так было на ПК Б и ПК В), пользователь почти наверняка запускает не ту.

## 4. Порядок диагностики (дерево решений)

Проверять **строго сверху вниз**: каждый уровень держит все уровни ниже.

### Шаг 0. Снимок состояния

```powershell
Get-PnpDevice | Where-Object { $_.InstanceId -like '*VID_04A9*' } | ForEach-Object {
  $pc  = (Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName 'DEVPKEY_Device_ProblemCode').Data
  $svc = (Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName 'DEVPKEY_Device_Service').Data
  $last= (Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName 'DEVPKEY_Device_LastArrivalDate').Data
  "{0,-7} {1,-6} {2,-30} svc={3,-9} prob={4,-3} last={5}  {6}" -f $_.Status,$_.Class,$_.FriendlyName,$svc,$pc,$last,$_.InstanceId
}
```

`LastArrivalDate` даёт таймлайн: когда какой узел приходил последний раз. На ПК Б именно так нашли момент поломки.

### Шаг 1. Физический уровень

| Что видим | Проблема |
|---|---|
| Присутствующих узлов `VID_04A9` **нет вообще**, при перетыкании кабеля система не выдаёт ничего, аппарата нет и в сети | **П10** — кабель не в том разъёме. Чинит человек. |
| Родитель есть, но в `problem 10`, серийника в Instance ID нет (вид `5&xxxx&0&N`), `MI_00`/`MI_01` нет | **П7** — отвал по USB/питанию. Чинит человек (выключить из розетки). В устройства не лезть. |
| Родитель в `problem 0` по серийнику | идём дальше |

### Шаг 2. Уровень интерфейсов

| Что видим | Проблема |
|---|---|
| Есть узел `...&PI_00\...` класса USB со службой `usbprint`, узла `MI_00` класса Image нет | **П1** (даже если скан в Windows работает — см. П11) |
| `MI_00` класса Image есть, но его пакет `mfscn.inf` не под PID устройства | **П2** |
| `MI_01` в `problem 10`, родитель при этом в порядке | **П6** |
| Три узла в норме | идём дальше |

**Если П1 подтверждена — сначала лечить её, и только потом печать.** Пока Interface 0 захвачен, печать может не работать вообще (П12), и все правки печати будут бесполезны.

### Шаг 3. Уровень печати

```powershell
Get-Printer | Select-Object Name, DriverName, PortName, PrinterStatus, Default
Get-PrinterPort | Where-Object Name -like 'USB*' | Select-Object Name, Description
```

| Что видим | Проблема |
|---|---|
| Очередь на `Microsoft IPP Class Driver` | **П3** |
| Принтер по умолчанию — сетевая очередь (`WSD-…`, IPP) при подключении по USB | **П14** |
| Порт с описанием `UnknownPrinter` | **П4** |
| Описание порта нормальное, но задания висят / очередь offline | сверить `Device Id` и `Device Path` с живым `MI_01` — **П4** (скрытая форма) |
| Ошибка `CnXP0PP.DLL`, `0x20` | **П5** |
| Очередь Canon на USB-порту другого производителя (`VID_03F0` — HP и т. п.) | мусор, см. П14 |

### Шаг 4. Сканер на уровне Windows (WIA)

```powershell
$dm = New-Object -ComObject WIA.DeviceManager
foreach ($d in $dm.DeviceInfos) { "{0}  |  {1}" -f $d.Properties('Name').Value, $d.DeviceID }
```

| Что видим | Проблема |
|---|---|
| Только сетевой сканер, ошибка `0x80210006` («устройство занято») | **П8** + проверить П1 |
| Сканер с ID `SWD\EsclUsb\{…}` (Microsoft eSCL), сканера `{6BDD1FC6-…}\NNNN` нет | **П11**: Windows сканирует, программы Canon — нет |
| Сканер `{6BDD1FC6-…}\NNNN` есть | драйвер Canon подключён, идём дальше |

Проверять **реальным сканом в файл**, а не наличием устройства в списке (способ — в разделе 10).

### Шаг 5. Сканер на уровне программы Canon

| Что видим | Проблема |
|---|---|
| Программа пишет «драйвер сканера, поддерживающий это ПО, не установлен» | не та программа для этого PID — **П9** |
| Программа пишет «связь не установлена», а WIA-скан работает | не та программа (**П9**), сетевой профиль (**П8**) или профиль-пустышка (**П13**) |
| В поле «Сканер» / «Название продукта» стоит `… Network` | **П8** |
| В поле стоит общее имя вроде `Canon MF Scan` вместо модели | **П13** |

### Шаг 6. Финальная проверка

- реальный скан через WIA в файл;
- реальный скан через ту программу Canon, которой пользуется человек;
- тестовая страница печати **и проверка листа глазами** (журнал не доказывает качество, см. П3);
- принтер по умолчанию — рабочая USB-очередь;
- полный цикл переподключения (выключить/включить родительский узел или переткнуть кабель) — после него всё должно подняться само.

## 5. Проблемы и решения

### П1. Windows отдала канал сканера принтерному драйверу

**Где встретилось:** ПК А, ПК Б, ПК В — **на всех трёх**.

**Суть.** В системном `usbprint.inf` есть очень широкое правило:
```
%USBPRINT.DeviceDesc% = USBPRINT_Inst, USB\Class_07, GENERIC_USB_PRINTER
```
Оно подходит под любой интерфейс принтерного класса, включая Interface 0, который должен достаться сканеру. В результате вместо `MI_00` (Image, `usbscan`, драйвер Canon) появляется `PI_00` (USB, `usbprint`). Правильный `MI_00` остаётся «призраком» в реестре (`Present = False`).

**Когда случается.** При переподключении USB: перестановка кабеля, отвал по питанию, выход из сна. На ПК Б по таймлайну: утром `MI_00` ещё приходил, после переподключения днём вместо него пришёл `PI_00`.

**Последствия:**
- программы Canon не видят сканер («связь не установлена»);
- WIA-сканер Canon отсутствует; вместо него может быть нерабочая заглушка eSCL («device is not online», ПК А) или рабочий eSCL-сканер Windows (ПК В, см. П11);
- **печать может не работать тоже** (ПК В, см. П12).

**Как распознать:**
```powershell
Get-PnpDevice -PresentOnly | Where-Object InstanceId -match 'VID_04A9.*PI_00'
```
Если что-то нашлось и узла `MI_00` класса Image нет — это П1.

**Решение (одинаковое на всех трёх ПК).** Выключить и включить узел `PI_00`: Windows заново подберёт драйвер и на этот раз применит пакет Canon. Ничего не устанавливается.

```powershell
$pi = (Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -match 'VID_04A9.*PI_00' }).InstanceId
Stop-Service stisvc -Force
Disable-PnpDevice -InstanceId $pi -Confirm:$false
Start-Sleep 5
Enable-PnpDevice  -InstanceId $pi -Confirm:$false
pnputil /scan-devices
Start-Service stisvc
```

Альтернативный поиск узла (если имя другое): узел `VID_04A9` со службой `usbprint`, который **не** `MI_01`:
```powershell
$pi = (Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -match 'VID_04A9' -and
       (Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName 'DEVPKEY_Device_Service').Data -eq 'usbprint' -and
       $_.InstanceId -notmatch 'MI_01' }).InstanceId
```

**Как отличалось:**
| ПК | Что было после переэнумерации |
|---|---|
| А | сразу `MI_00` + правильный пакет драйвера |
| Б | сначала узел остался `PI_00`, но уже класса Image с драйвером Canon и сканер заработал; после полного переподключения сам переехал на `MI_00` |
| В | `MI_00` + драйвер Canon; побочно исчез eSCL-сканер Windows и сама поднялась печать (П12); остался лишний профиль ScanGear (П13) |

**Проверка:** узел класса Image со службой `usbscan`, в WIA есть устройство `{6BDD1FC6-…}\NNNN`, реальный скан в файл проходит.

**Откат:** полностью обратимо — `pnputil /scan-devices` или переподключение кабеля.

**Профилактика:** раздел 8.

### П2. Установлен пакет драйвера сканера не для той модели

**Где встретилось:** только ПК А. На ПК Б и ПК В проверено — драйвер был правильный.

**Суть.** В хранилище драйверов лежат два пакета `mfscn.inf` для разных PID (таблица в разделе 3). Установщик Canon сделал активным пакет от другой ревизии аппарата. На ПК А одновременно стояли `Canon MF460 Series 7.8.5.0` и `Canon MF460 II Series MF ScanGear 3.6.0.0`.

Номера `oemXX.inf` на каждом ПК разные (ПК А: `oem3`/`oem86`; ПК Б: `oem7`/`oem119`; ПК В: `oem154` — нужный), поэтому ориентироваться на PID внутри пакета.

**Как распознать:**
```powershell
pnputil /enum-drivers | Select-String -Context 0,6 'mfscn'
```
Для каждого пакета открыть его `.inf` в `C:\Windows\INF\oemXX.inf` и найти строки `PID_XXXX` — сравнить с PID устройства.

**Решение.** На ПК А нужный пакет уже лежал в хранилище — хватило переэнумерации из П1, Windows выбрала подходящий сама.

**Правило:** не переустанавливать драйверы Canon поверх, пока не убедились, что нужного пакета действительно нет. На ПК Б переустановка сломала бы рабочую печать.

### П3. Очередь печати на Microsoft IPP Class Driver

**Где встретилось:** ПК А и ПК В. На ПК Б очередь изначально стояла на драйвере Canon.

**Суть.** Драйвер Microsoft IPP работает через Interface 0 (IPP-over-USB) — тот самый, который должен принадлежать сканеру. Кроме того, он шлёт универсальный поток, а аппарат понимает собственные языки Canon (`LIPSLX`, `CPCA`).

**Как проявлялось:**
| ПК | Симптом |
|---|---|
| А | задание не создавалось вообще, `Print()` падал с `Win32Exception: "The operation completed successfully"`, в журнале печати пусто |
| В | как только связь восстановилась, аппарат выдал **пачку почти пустых листов с артефактами** |

**Важно (ПК В):** в журнале службы печати такое задание числится **успешным** — событие 307, код `0x0`, «Страниц напечатано: 1». Журнал **не доказывает**, что лист вышел нормальным. Косвенный признак — размер: одна и та же тестовая страница через IPP весила ~238 КБ, через драйвер Canon ~4,6 КБ.

**Как распознать:**
```powershell
Get-Printer | Where-Object Name -like '*Canon*' | Select-Object Name, DriverName, PortName
```

**Решение.**
1. Проверить, что выключен Windows Protected Print Mode (иначе сторонние драйверы Canon не заработают). На ПК А проверялось отдельно.
2. Найти драйвер Canon в системе:
   ```powershell
   Get-PrinterDriver | Where-Object Name -like '*Canon*' | Select-Object Name
   ```
3. Создать очередь на драйвере Canon на порту печати (`MI_01`), удалить IPP-очередь:
   ```powershell
   Add-Printer -Name 'Canon MF460 USB (UFR II)' -DriverName '<Canon Generic Plus UFR II …>' -PortName '<USB-порт>'
   Remove-Printer -Name '<IPP-очередь>'
   ```
4. Назначить новую очередь принтером по умолчанию (см. П14).

Версии драйвера на ПК: А — `V280`, Б — `v3.40`, В — `V290`. Брать тот, что уже есть в системе.

**Побочный эффект (ПК В):** после удаления IPP-очереди узел `USBPRINT\…` сам перепривязался к драйверу Canon. Значит, если Windows пересоздаст очередь автоматически, она будет правильной.

**Порядок:** сначала П1, потом П3.

### П4. Протухшие идентификаторы USB-порта печати

**Где встретилось:** ПК А и ПК В — ломало печать. ПК Б — расхождение было, но безвредное.

**Суть.** В ветке порта
```
HKLM:\SYSTEM\CurrentControlSet\Control\Print\Monitors\USB Monitor\Ports\USBxxx
```
хранятся `Device Id`, `Device Path` и `Parent Device Id`. Средний номер в Instance ID (`6&xxxxxxxx&N&0001`) — счётчик экземпляра, он **меняется при переезде аппарата в другой USB-разъём компьютера**. Если запись порта не обновилась, спулер не находит устройство.

**Две формы:**

| Форма | ПК | Признаки |
|---|---|---|
| Явная | А | описание порта `UnknownPrinter`; задания спулятся, висят в статусе «Печать, сохранено» бесконечно; `CreateFile` на интерфейс открывается, `WriteFile` блокируется навсегда |
| Скрытая | В | описание порта **нормальное** (`CanonMF460 Series UFR II`), `Parent Device Id` верный, но `Device Id` и `Device Path` протухли, причём по-разному; очередь offline, задания висят |

Пример со ПК В:
```
Device Id   : ...\6&26ffc978&0&0001     ← 0
Device Path : ...#6&26ffc978&2&0001#... ← 2
живой MI_01 : ...\6&26ffc978&3&0001     ← на самом деле 3
```

**Как распознать — всегда сверять с живым узлом, независимо от описания порта:**
```powershell
# живой узел печати
Get-PnpDevice -PresentOnly | Where-Object InstanceId -match 'VID_04A9.*MI_01' | Select-Object -ExpandProperty InstanceId

# что записано в порту (подставить номер порта очереди)
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Print\Monitors\USB Monitor\Ports\<USBxxx>' |
  Select-Object 'Device Id', 'Device Path', 'Parent Device Id'

# реальные пути интерфейсов печати — не сочинять вручную, брать отсюда
Get-ChildItem 'HKLM:\SYSTEM\CurrentControlSet\Control\DeviceClasses\{28d78fad-5a12-11d1-ae5b-0000f803a8c2}' |
  ForEach-Object { "{0}`n  {1}" -f $_.PSChildName, (Get-ItemProperty $_.PSPath).DeviceInstance }
```

**Решение.**
```powershell
Stop-Service Spooler -Force
$p = 'HKLM:\SYSTEM\CurrentControlSet\Control\Print\Monitors\USB Monitor\Ports\<USBxxx>'
Set-ItemProperty $p -Name 'Device Id'   -Value '<Instance ID живого MI_01>'
Set-ItemProperty $p -Name 'Device Path' -Value '<путь интерфейса из DeviceClasses>'
Start-Service Spooler
```

**Исключение (ПК Б):** печать шла через Dynamic Print Monitor, описание порта правильное, задания уходили — расхождение `Device Id` оставили как есть. Правило: если печать реально проходит (лист выходит, очередь пустеет), не трогать.

**Важно (ПК В):** правка порта **сама по себе печать не подняла** — она заработала только после П1 (см. П12).

### П5. Сломанный print processor Canon

**Где встретилось:** только ПК А. На ПК Б и ПК В родной `CnXP0PP` работает.

**Суть.** Спулер не смог загрузить `CnXP0PP.DLL` (ошибка `0x20`, `ERROR_SHARING_VIOLATION`).

**Решение** — переключить очередь на стандартный процессор Windows:
```powershell
$pk = 'HKLM:\SYSTEM\CurrentControlSet\Control\Print\Printers\<имя очереди>'
Set-ItemProperty $pk -Name 'Print Processor' -Value 'winprint'
Set-ItemProperty $pk -Name 'Datatype'        -Value 'RAW'
```
Применять **только** при этой конкретной ошибке. Причина её появления на ПК А не выяснена.

### П6. Узел печати `MI_01` в Code 10 после ручных правок

**Где встретилось:** только ПК А, побочный эффект ремонта.

**Решение:** удалить узел и перезапустить родителя:
```powershell
pnputil /remove-device "<Instance ID узла MI_01>"
Disable-PnpDevice -InstanceId '<Instance ID родителя>' -Confirm:$false
Start-Sleep 5
Enable-PnpDevice  -InstanceId '<Instance ID родителя>' -Confirm:$false
pnputil /scan-devices
```
**Не путать с П7:** здесь родитель в порядке, сломан только `MI_01`.

### П7. Аппарат «отвалился» по USB или питанию

**Где встретилось:** ПК А, отдельным инцидентом уже после ремонта.

**Суть.** Аппарат отключился от шины и вернулся в нерабочем состоянии: Windows видит устройство, но оно не отвечает. Драйверы и настройки целы.

**Как распознать:**
- перестали работать **и печать, и скан** одновременно;
- родительский `USB Composite Device` в `problem 10`;
- в Instance ID родителя **пропал серийник** (было `…\<12 hex>`, стало `…\5&xxxx&0&N`) — надёжный признак сбоя железа, а не драйверов;
- узлов `MI_00`/`MI_01` нет;
- расширенный статус `0xC000000E` (`STATUS_NO_SUCH_DEVICE`):
  ```powershell
  (Get-PnpDeviceProperty -InstanceId '<Instance ID родителя>' -KeyName 'DEVPKEY_Device_ProblemStatus').Data
  # 3221225486 = 0xC000000E
  ```

**Решение:**
1. Выключить принтер кнопкой → вынуть кабель питания на 15 секунд → включить, дождаться готовности. На ПК А помогло сразу, всё вернулось само, зависшее задание допечаталось.
2. Если не помогло — переткнуть USB-кабель.
3. Затем — порт на задней панели компьютера, без хаба.

**Не делать:** `pnputil /remove-device`, выключение/включение узлов. Аппарат не отвечает, такая «хирургия» ничего не даст и может сломать привязки.

**Если повторяется после профилактики (раздел 8)** — железо: кабель (короче, с ферритом), порт, питание или прошивка аппарата.

**Для программы:** автоматически не чинится — попросить человека.

### П8. Нерабочий сетевой сканер маскирует проблему

**Где встретилось:** ПК Б. На ПК В сетевые узлы тоже были, но это разобрано в П14.

**Суть.** Аппарат подключён по USB, но в системе висит сетевой вариант сканера, нацеленный на IP принтера. Сетевое сканирование на аппарате выключено (порты 8610/8612 закрыты), поэтому сканер работать не может. Мешает на двух уровнях:
- **Windows:** был единственным сканером в списке и выдавал `0x80210006` (`WIA_ERROR_BUSY`, «устройство занято») вместо честного «сканера нет» — из-за этого П1 было трудно заметить;
- **программа Canon:** MF Scan Utility 2 при первом запуске выбрала сетевой профиль.

**Как распознать:** в списке WIA есть устройство со словом `Network` или узел `ROOT\CANON_MF_NETWORK\…`; в программе Canon выбран вариант `… Network`; в ScanGear две записи с почти одинаковыми именами, обе `AvailableDriver = 1`.

**Решение (всё обратимо, драйверы не трогаются):**
1. Отключить (не удалять) сетевой WIA-узел:
   ```powershell
   Disable-PnpDevice -InstanceId 'ROOT\CANON_MF_NETWORK\0000' -Confirm:$false
   ```
2. Скрыть сетевую запись ScanGear (ветка `SateraMFP3` для `28DC`, `SateraMFP1` для `28B5`; номер версии `11.3` может отличаться):
   ```powershell
   $root = 'HKLM:\SOFTWARE\WOW6432Node\Canon\SateraMFP3\ScanGear\11.3\Devices'
   $net = (Get-ChildItem $root | Where-Object { (Get-ItemProperty $_.PSPath).ProductName -match 'Network' }).PSPath
   Set-ItemProperty $net -Name AvailableDriver -Value 0 -Type DWord
   ```
3. В `HKCU\SOFTWARE\Canon\IJNetworkScannerSelectorEX2\Devices\<модель>_<MAC>` перевести `Select` и `Check` в `0`.
4. Сбросить запомненный выбор программы: сделать копию и удалить `%APPDATA%\Canon\MF Scan Utility 2\UICOM.DAT` и папку `… Network` рядом.

После перезапуска программа сама выбирает USB-сканер.

**Если сетевое сканирование понадобится:** включить в веб-интерфейсе принтера, затем вернуть всё обратно.

### П9. Запускается программа сканирования не для этой модели

**Где встретилось:** ПК Б и ПК В — в зеркальном виде.

**Суть.** На ПК стоят утилиты Canon от обеих моделей, а в панели задач или «Пуске» закреплена неподходящая.

| Программа | Таблицы интерфейса | Для какого PID |
|---|---|---|
| Canon MF Scan Utility 1.21 | `CNUI001`…`CNUI013`, `CNUIG01` | `28B5` (MF460 Series) |
| Canon MF Scan Utility 2 (2.0.x) | `CNUI015`, `CNUI016`, `CNCLID28.dll` | `28DC` (MF460 II Series) |
| Canon Scan Utility (2.0.x) | своих таблиц нет — оболочка к версии 2 | `28DC` |

| ПК | Что было | Что нужно |
|---|---|---|
| Б (`28DC`) | закреплена MF Scan Utility 1.21, к тому же настроенная на чужую модель (`Canon MF460 Series` без II); при ручной правке она сама возвращала настройку обратно | Canon Scan Utility / MF Scan Utility 2 |
| В (`28B5`) | версия 2 и Canon Scan Utility писали «драйвер сканера, поддерживающий это ПО, не установлен» | MF Scan Utility 1.21 |

**Универсальный способ выбора, не зависящий от модели:** взять имя таблицы интерфейса из профиля ScanGear этого аппарата и найти, в папке какой утилиты она лежит.

```powershell
# все профили ScanGear
Get-ChildItem 'HKLM:\SOFTWARE\WOW6432Node\Canon' -Recurse -ErrorAction SilentlyContinue |
  Where-Object { $_.PSParentPath -like '*ScanGear*Devices' } | ForEach-Object {
    $q = Get-ItemProperty $_.PSPath
    "[{0}] {1} | AvailableDriver={2} | UI={3}" -f $_.PSChildName, $q.ProductName, $q.AvailableDriver, $q.CaddisUIPath }

# где лежит нужная таблица
$ui = '<CaddisUIPath рабочего профиля, например CNUI012.TBL или CNUI016.TBL>'
Get-ChildItem 'C:\Program Files (x86)\Canon' -Recurse -Filter $ui | Select-Object FullName
```

Программа, в папке которой нашлась таблица, — правильная.

**Решение:**
- ПК Б: удалили MF Scan Utility 1.21 штатным деинсталлятором (`MAINT.exe /UninstallRemove uninst.ini`), закрепили `C:\Program Files (x86)\Canon\Scan Utility\SCANUTILLA.exe`.
- ПК В: ничего не удаляли, указали пользователю нужную: `C:\Program Files (x86)\Canon\MF Scan Utility\MFSCANUTILITY.exe` («Canon MF Scan Utility» без цифры 2). В поле «Название продукта» — `Canon MF460 Series`.

Удалять лишнюю программу — по ситуации: удаление надёжнее (её не запустят по ошибке), оставить — безопаснее (если аппарат заменят на другую модель).

### П10. USB-кабель воткнут в сетевой разъём принтера

**Где встретилось:** ПК В.

**Суть.** Со стороны аппарата кабель сидел в разъёме LAN вместо квадратного USB-B. Компьютер не видел устройство по USB, и одновременно аппарат пропал из сети, потому что сетевой разъём был занят. Внешне — «не работает ничего».

**Как распознать:**
- присутствующих узлов `VID_04A9` нет **совсем** — ни в норме, ни в `problem 10`; в лучшем случае старый «призрак» с давней датой;
- при перетыкании кабеля система не выдаёт **ничего** — даже `Unknown USB Device (Device Descriptor Request Failed)`;
- аппарата нет и в сети: ARP-запись `Incomplete`, порты закрыты, mDNS-имя не разрешается;
- USB-шина компьютера исправна — другие устройства определяются;
- политик запрета установки устройств нет, службы `usbccgp`/`usbprint`/`usbscan` в штатном режиме.

**Отличие от П7:** при П7 родитель виден в `problem 10` без серийника. Здесь родителя нет вообще.

**Надёжная проверка** — мониторинг устройств во время перетыкания кабеля (около 5 минут):
```powershell
$snap = @{}
foreach ($d in Get-PnpDevice -PresentOnly) { $snap[$d.InstanceId] = $d.Status }
$end = (Get-Date).AddSeconds(295)
while ((Get-Date) -lt $end) {
  $now = @{}
  foreach ($d in Get-PnpDevice -PresentOnly) { $now[$d.InstanceId] = $d.Status }
  foreach ($k in $now.Keys)  { if (-not $snap.ContainsKey($k)) { "+ $(Get-Date -f HH:mm:ss) $k" } }
  foreach ($k in $snap.Keys) { if (-not $now.ContainsKey($k))  { "- $(Get-Date -f HH:mm:ss) $k" } }
  $snap = $now
  Start-Sleep -Milliseconds 1200
}
```
Ноль строк за всё время перетыкания = сигнал до контроллера не доходит.

**Решение:** переставить кабель в квадратный USB-B на задней панели аппарата.

**Для программы:** чинит только человек. Просить проследить кабель от разъёма на принтере до компьютера.

**Что вылезло после:** когда связь появилась, обнаружились П1, П3, П4, П12, П13, П14 — накопленные прошлыми попытками настройки.

### П11. `PI_00` есть, а сканер в Windows работает — признак П1 без симптома

**Где встретилось:** ПК В.

**Суть.** На Windows 11 build 26200 через захваченный `usbprint` интерфейс Windows сама поднимает узел `SWD\ESCLUSB\{…}` с драйвером **Microsoft eSCL Class Driver**, и сканирование средствами Windows работает. Узел `PI_00` есть, `MI_00` нет — а «сканер не работает» не наблюдается.

На ПК А было похожее, но там eSCL-узел не имел связи с железом и выдавал «device is not online». То есть eSCL-заглушка бывает и рабочей, и мёртвой.

**Программам Canon такой сканер не годится:** они работают через ScanGear, а тот ищет узел Image со службой `usbscan` и драйвером `mfscn`.

**Чем опасно:** легко решить «лечить нечего, скан же работает» — или наоборот побояться трогать `PI_00`.

**Как распознать:** в WIA есть устройство с ID `SWD\EsclUsb\{…}`, а устройства `{6BDD1FC6-…}\NNNN` (Canon) нет.

**Правило:** проверять не наличие `MI_00`, а **оба уровня** — WIA-скан и программу Canon. П1 применять, если нужны программы Canon (почти всегда нужны).

**Побочный эффект лечения:** eSCL-узел исчезнет, его заменит WIA-устройство Canon. Сканирование средствами Windows сохранится — через драйвер Canon.

### П12. П1 лечит не только сканер, но и печать

**Где встретилось:** ПК В.

**Суть.** Пока Interface 0 занят `usbprint` в виде `PI_00`, печать через Interface 1 конфликтует с ним: очередь уходит в offline, задания висят со статусом «Ошибка | Печать», напечатано 0 страниц.

**Как распознать:**
- в ветке очереди `Status = 128` или `384`, `ExtendedPrinterStatus = 9`;
- `DetectedErrorState = 0`, в журналах службы печати пусто;
- порт и его идентификаторы уже выверены (П4 исправлена) — а печати нет.

**Решение:** П1. Сразу после переэнумерации `PI_00` очередь выходит из offline без каких-либо действий с печатью.

**Вывод:** порядок «сначала П1, потом печать» — не рекомендация, а условие.

### П13. После лечения П1 в ScanGear остаётся профиль-пустышка

**Где встретилось:** ПК В.

**Суть.** Пока узел висел на `PI_00`, драйвер Canon зарегистрировал в ScanGear **общий** профиль (имя вроде `Canon MF Scan`, общая таблица интерфейса). После переезда на `MI_00` появился правильный профиль под модель, но старый остался, и оба `AvailableDriver = 1`. Программа Canon берёт первый — пустышку — и пишет «невозможно установить связь со сканером».

**Как распознать:** в ветке `Devices` ScanGear два подраздела с `AvailableDriver = 1`, разными `ProductName` и `CaddisUIPath`. В программе в поле «Название продукта» общее имя вместо модели. Команда — в П9.

**Какой профиль правильный:** тот, чей `CaddisUIPath` совпадает с тем, что требует драйвер живого устройства (на ПК В — `CNUI012.TBL`), и чей `InstallDirectory` указывает на папку модели в `C:\Windows\TWAIN_32\` (на ПК В — `…\TWAIN_32\MF460\`).

**Решение (обратимое, как в П8):**
```powershell
Set-ItemProperty 'HKLM:\SOFTWARE\WOW6432Node\Canon\SateraMFP1\ScanGear\11.3\Devices\<пустышка, на ПК В — MFSCN>' `
  -Name AvailableDriver -Value 0 -Type DWord
Restart-Service stisvc -Force
```

### П14. Следы другого аппарата Canon; мёртвая очередь по умолчанию

**Где встретилось:** ПК В — с последствиями. ПК Б — похожие следы, безвредные.

**Суть.** На ПК В жил сетевой профиль аппарата (`SWD\IPP` + `SWD\ESCL`) с очередью печати на порту `WSD-…` и сетевым сканером, настроенный за две недели до ремонта. Эта сетевая очередь стояла **принтером по умолчанию**. При проверке выяснилось, что профиль принадлежит **другой физической машине**: другая модель (MF460 II Series), другой аппаратный адрес, другое mDNS-имя. Всё, что печаталось обычным способом, уходило в никуда.

Также на ПК В нашлось:
- очередь `Canon Generic Plus UFR II V290` на `USB001`, а `USB001` привязан к устройству HP (`VID_03F0`); очередь в `PendingDeletion`, в ней застряла пробная страница двухнедельной давности;
- осиротевший ключ очереди `Canon MF460 II Series,3` (без драйвера, порта, процессора);
- порт `USB002` — устаревший, с таким же расхождением идентификаторов.

На ПК Б: ветки `SateraMFP1`, папка `%APPDATA%\Canon\MF460`, порты `USB001/002/004` от `PID_28B5` — следы аппарата другой модели. Именно они увели старую программу на чужую модель (П9).

**Как распознать:**
- сравнить модель и идентификаторы сетевых узлов (`DEVPKEY_DeviceContainer_ModelName`, аппаратный адрес) с моделью и серийником живого USB-устройства — не совпали, значит разные аппараты;
- проверить принтер по умолчанию: `Get-Printer | Where-Object Default`;
- проверить, к какому устройству привязан каждый USB-порт с очередью Canon (`Parent Device Id` в ветке порта).

**Решение:**
1. Снять зависшие задания.
2. Отключить (не удалять) сетевые узлы:
   ```powershell
   Disable-PnpDevice -InstanceId '<SWD\ESCL\… и SWD\IPP\… сетевого аппарата>' -Confirm:$false
   ```
3. Назначить рабочую USB-очередь по умолчанию и запретить Windows переставлять её:
   ```powershell
   Invoke-CimMethod -InputObject (Get-CimInstance Win32_Printer | Where-Object Name -eq '<USB-очередь>') -MethodName SetDefaultPrinter
   Set-ItemProperty 'HKCU:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows' -Name 'LegacyDefaultPrinterMode' -Value 1 -Type DWord
   ```
4. Остальной мусор (старые порты, осиротевшие ключи) — не трогать, если не мешает: ни одна очередь их не использует, а удаление рискует задеть рабочую печать. На ПК В удаление ключа `…,3` заблокировала защита среды.

После ремонта сетевые узлы на ПК В Windows убрала сама — аппарата в сети не существует.

## 7. Печать — какой драйвер и как проверять результат

- Рабочий драйвер: **Canon Generic Plus UFR II** (любая версия, уже установленная в системе).
- Не рабочий в этой схеме: **Microsoft IPP Class Driver** (П3).
- Порт: USB-порт, привязанный к живому `MI_01` данного аппарата (не к чужому устройству).
- Print processor: `CnXP0PP / RAW` по умолчанию; `winprint / RAW` — только при ошибке П5.
- Принтер по умолчанию — эта очередь, `LegacyDefaultPrinterMode = 1`.

**Проверка результата печати:**
- очередь пустеет за секунды, `JobCount = 0`;
- в журнале цепочка событий 801 → 842 → 805 → 307;
- **лист проверен глазами.** Событие 307 с кодом `0x0` есть и у «мусорной» печати через IPP (ПК В).

## 8. Профилактика (применено на всех трёх ПК)

Самый частый провокатор П1 и П7 — энергосбережение USB. Для стационарных ПК без батареи:

**1. Запрет отключать корневой USB-хаб ради экономии энергии:**
```powershell
Get-CimInstance -Namespace root\wmi -ClassName MSPower_DeviceEnable |
  Where-Object { $_.InstanceName -match 'ROOT_HUB30' } |
  ForEach-Object { Set-CimInstance -InputObject $_ -Property @{Enable=$false} }
```
Вручную: Диспетчер устройств → USB Root Hub (USB 3.0) → Свойства → Управление электропитанием → снять «Разрешить отключение этого устройства для экономии энергии».

**2. Отключение USB selective suspend:**
```powershell
powercfg /setacvalueindex SCHEME_CURRENT 2a737441-1930-4402-8d77-b2bebba308a3 48e6b7a6-50f5-4782-a5d4-53bb8f07e226 0
powercfg /setdcvalueindex SCHEME_CURRENT 2a737441-1930-4402-8d77-b2bebba308a3 48e6b7a6-50f5-4782-a5d4-53bb8f07e226 0
powercfg /setactive SCHEME_CURRENT
```
Проверка (вывод локализован, искать по значению):
```powershell
powercfg /q SCHEME_CURRENT 2a737441-1930-4402-8d77-b2bebba308a3 48e6b7a6-50f5-4782-a5d4-53bb8f07e226 |
  Select-String -Pattern '0x0000'
```
Оба индекса `0x00000000` = отключено.

**3. Физика:** кабель в USB-B на задней панели аппарата; на компьютере — порт на задней панели, без хабов; кабель по возможности короткий.

## 9. Страховка и откат

### Перед любым ремонтом
1. Точка восстановления Windows (нужны права администратора).
2. Экспорт в `C:\fix\backup\` веток реестра:
   - `HKLM\SYSTEM\CurrentControlSet\Control\Print\Monitors\USB Monitor\Ports`
   - `HKLM\SYSTEM\CurrentControlSet\Control\Print\Printers`
   - `HKLM\SYSTEM\CurrentControlSet\Control\Print\Monitors`
   - ветки Canon: `HKLM\SOFTWARE\Canon`, `HKLM\SOFTWARE\WOW6432Node\Canon`, `HKCU\SOFTWARE\Canon`
   - `HKLM\SYSTEM\CurrentControlSet\Enum\USB\VID_04A9*`
   - класс Image
3. JSON-снимки: устройства, принтеры, порты — до ремонта.
4. Копия `%APPDATA%\Canon\`.
5. Копия зависших заданий из папки спулера перед их удалением.

### Откат
- Точка восстановления: Пуск → Восстановление → Запуск восстановления системы.
- `.reg`-файлы: двойной клик или `reg import <файл>`.
- Настройки программ Canon: копировать обратно в `%APPDATA%\Canon\`.
- П1: `pnputil /scan-devices` или переподключение кабеля.
- Отключённые узлы: `Enable-PnpDevice -InstanceId '<ID>' -Confirm:$false`.
- Скрытые профили ScanGear: `AvailableDriver = 1`.
- Энергосбережение USB: вернуть галку в Диспетчере устройств; `powercfg … 1`.

### Чего не делать без крайней необходимости
- переустанавливать драйверы Canon поверх;
- удалять устройства через `pnputil /remove-device` при П7/П10;
- удалять (вместо отключения) сетевые узлы и профили;
- трогать старые порты и ключи, если ни одна очередь их не использует.

## 10. Технические заметки

### Сканирование через WIA из PowerShell

**Драйвер Canon (`mfscn`)** ведёт себя нестандартно:
- `$dev.Items.Item(1)` возвращает пустоту — элемент доставать через `InvokeMember`;
- `Transfer` с идентификатором формата в аргументе возвращает пустоту **без ошибки** — вызывать **без параметров**, формат берётся из `Preferred Format`.

```powershell
$dm   = New-Object -ComObject WIA.DeviceManager
$di   = $dm.DeviceInfos | Where-Object { $_.DeviceID -like '{6BDD1FC6*' } | Select-Object -First 1
$dev  = $di.Connect()
$item = [System.__ComObject].InvokeMember('Item', 'GetProperty', $null, $dev.Items, @(1))
$img  = $item.Transfer()
$img.SaveFile("$([Environment]::GetFolderPath('Desktop'))\scan.bmp")
```

**Драйвер Microsoft eSCL:** оба привычных способа работают.

Полезные свойства устройства: `Document Handling Select` (1 — автоподатчик, 2 — планшет), `Document Handling Status` (бит `0x02` — планшет готов, бит `0x20` — замятие).

Норма скана планшета: 24 бита, 300 dpi, около 2550×3508 (A4), до 600 dpi.

### Журнал службы печати

По умолчанию выключен. Включить на время:
```powershell
wevtutil sl Microsoft-Windows-PrintService/Operational /e:true
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PrintService/Operational'; StartTime=(Get-Date).AddMinutes(-10)}
```
- 310 — задание удалено без печати;
- 801 → 842 → 805 → 307 — дошло до аппарата; 842 называет драйвер и процессор печати;
- 307 с кодом `0x0` **не гарантирует** нормальный лист.

После диагностики вернуть журнал в исходное состояние.

### Полезные команды

```powershell
# пакеты драйверов Canon
pnputil /enum-drivers | Select-String -Context 0,6 'Canon'

# программы Canon
Get-ItemProperty 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*',
                 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object DisplayName -like '*Canon*' | Select-Object DisplayName, DisplayVersion

# расширенный статус проблемы узла
(Get-PnpDeviceProperty -InstanceId '<ID>' -KeyName 'DEVPKEY_Device_ProblemStatus').Data

# Windows Protected Print Mode — проверить, что выключен (нужен для драйверов Canon)
```

## 12. Выводы и правила для будущей программы

### Выводы
1. **П1 — везде.** Windows 11 отдаёт канал сканера принтерному драйверу при любом переподключении USB. Лечится переэнумерацией без установки чего-либо.
2. **Всё определяется PID.** Драйвер сканера, ветка ScanGear и программа сканирования для `28B5` и `28DC` разные. Программы от «соседней» модели не работают.
3. **Уровни держат друг друга:** кабель → родитель → интерфейсы → печать / сканер Windows → программа Canon. Чинить сверху вниз. Правки нижних уровней бесполезны, пока сломан верхний.
4. **«Работает в Windows» ≠ «работает у человека».** Проверять WIA-скан и программу Canon, журнал печати и лист глазами.
5. **Правильный драйвер обычно уже есть.** Переустановка чаще ломает, чем чинит.
6. **Прошлые попытки настройки оставляют мусор** (сетевые профили, очереди других аппаратов, профили-пустышки, чужие программы), и он маскирует настоящие проблемы.
7. **Microsoft IPP Class Driver в этой схеме не работает** — ни по связи, ни по формату данных.

### Кандидаты в автоматические сценарии (if/else)

| Условие | Действие | Автоматически? |
|---|---|---|
| Нет узлов `VID_04A9` вообще | попросить проверить кабель (П10) | нет, человек |
| Родитель `problem 10` без серийника | попросить выключить принтер из розетки (П7) | нет, человек |
| Есть `PI_00` класса USB | переэнумерация (П1) | да |
| Пакет `mfscn` не под PID | П2 → если нужный пакет есть, переэнумерация; если нет — к Claude | частично |
| Очередь на Microsoft IPP | создать очередь на драйвере Canon, удалить IPP-очередь (П3) | да, если драйвер Canon есть |
| `Device Id`/`Device Path` порта ≠ живой `MI_01` | исправить (П4) | да |
| Ошибка `CnXP0PP` `0x20` | winprint / RAW (П5) | да |
| Принтер по умолчанию — не USB-очередь аппарата | переназначить (П14) | да |
| Сетевой сканер/профиль при USB-подключении | отключить, скрыть (П8) | да, спросив «сеть нужна?» |
| Два профиля ScanGear `AvailableDriver = 1` | скрыть пустышку (П13) | да |
| Программа не содержит таблицу из `CaddisUIPath` | указать правильную (П9) | да |
| Энергосбережение USB включено | отключить (раздел 8) | да |
| Любое другое | **передать Claude** с полным снимком состояния | — |

### Режимы программы
- **только диагностика** — показать, что найдено, ничего не менять;
- **ремонт** — с обязательной страховкой (раздел 9) перед первым изменением;
- **«попроси человека»** — для П7 и П10: показать инструкцию, дождаться «Готово», повторить диагностику;
- **финальная проверка** — раздел 4, шаг 6.

## 13. Открытые вопросы

- **Программа сканирования на ПК А** не проверялась. По правилу из П9 для `28B5` должна подойти MF Scan Utility 1.21 — стоит проверить.
- **Физический выход листа** подтверждён глазами только на ПК В. На ПК А и ПК Б — только на уровне системы.
- **Причина ошибки `CnXP0PP` (П5) на ПК А** не выяснена.
- **Мусор, оставленный намеренно:** старые порты и следы других аппаратов на ПК Б и ПК В. Чистка — отдельной задачей и только если начнёт мешать.
- **Сетевое сканирование** на аппаратах выключено. Если понадобится — включать в веб-интерфейсе принтера и возвращать сетевые узлы (обратные шаги П8/П14).
- Как поведут себя аппараты с другими PID той же серии (`28B4`, `28DB`) — не проверялось.
