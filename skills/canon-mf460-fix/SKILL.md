# Canon MF460 по USB — диагностика и ремонт

Полная база (14 проблем, команды, откат, технические заметки) лежит рядом: `reference.md`
(`%USERPROFILE%\.claude\skills\canon-mf460-fix\reference.md`). Читай из неё **нужные разделы по мере
продвижения**, а не целиком: §3 (PID), §4 (дерево диагностики), П1–П14 по номеру, §9 (страховка и откат), §10 (WIA из PowerShell).

## Что важно знать до начала

- Аппарат — составное USB-устройство. Interface 0 = сканер (`MI_00`, класс Image, служба `usbscan`, драйвер Canon `mfscn.inf`), Interface 1 = печать (`MI_01`, `usbprint`). Оба выглядят для Windows как принтер, и Windows часто отдаёт канал сканера драйверу `usbprint` (**П1**) — это было на всех трёх ПК.
- **Всё зависит от PID**: `28B5` = MF460 Series (ScanGear `SateraMFP1`, программа MF Scan Utility 1.21); `28DC` = MF460 II Series (`SateraMFP3`, MF Scan Utility 2 / Canon Scan Utility). Программы от соседней модели не работают. Надпись на корпусе — не аргумент.
- **Уровни держат друг друга**: кабель → родительский узел → интерфейсы → печать → WIA → программа Canon. Чинить строго сверху вниз; пока верхний уровень сломан, правки ниже бесполезны.
- Команды — PowerShell от администратора. Если доступен только Bash — `powershell -NoProfile -Command "..."`.
- Номера `oemXX.inf`, `USBxxx`, Instance ID на каждом ПК свои — команды из базы находят их сами, но перед изменением показывай, что именно нашлось.

## Правила безопасности

1. **Сначала только диагностика.** Пройти все уровни, ничего не меняя. Показать человеку список найденного (П-номера с признаками) и план правок. Менять — только после его «да». В режиме «только диагностика» — остановиться на отчёте.
2. **Перед первым изменением — страховка** (reference.md §9): точка восстановления (`Checkpoint-Computer`; если защита системы выключена — сказать и спросить, продолжать ли), экспорт веток реестра и JSON-снимков в `C:\fix\backup\<дата_время>\`, копия `%APPDATA%\Canon`.
3. **Отключать, а не удалять**: `Disable-PnpDevice`, `AvailableDriver = 0` — а не `pnputil /remove-device` и не удаление ключей реестра.
4. **Не переустанавливать драйверы Canon**, пока не проверен DriverStore (`pnputil /enum-drivers`). Нужный пакет почти всегда уже там; переустановка ломала рабочую печать.
5. **Если печать работает — проверять её после каждого шага** (тестовая страница, очередь пустеет). Сломалась — откатить последний шаг, прежде чем идти дальше.
6. **П7 и П10 чинит только человек.** Ничего не трогать в устройствах (никаких disable/remove). Дать инструкцию, дождаться «Готово», повторить диагностику с шага 0.
7. Одно изменение за раз; после каждого — перепроверка того же уровня.
8. Не трогать мусор, который ничему не мешает (старые порты, осиротевшие ключи, следы других аппаратов).

## Рабочий процесс

### Шаг 0. Снимок состояния
Снимок узлов `VID_04A9` с ProblemCode, Service, LastArrivalDate (§4 шаг 0); PID (§3); `Get-Printer`, `Get-PrinterPort`; список WIA-устройств. Сохранить как первый JSON-снимок в `C:\fix\backup\`.

### Уровень 1. Кабель — П10
Нет ни одного присутствующего узла `VID_04A9`, при перетыкании кабеля не появляется вообще ничего (даже `Unknown USB Device`) → кабель, скорее всего, в разъёме LAN вместо квадратного USB-B на задней панели. **Стоп**, инструкция человеку, ждать «Готово».

### Уровень 2. Родительский узел — П7
`USB Composite Device` в problem 10, в Instance ID **нет серийника** (вид `5&xxxx&0&N`), `MI_00`/`MI_01` нет → аппарат отвалился по USB/питанию. **Стоп**: выключить принтер кнопкой → вынуть питание на 15 с → включить → дождаться готовности. Не помогло — переткнуть кабель, потом порт на задней панели ПК без хаба.

### Уровень 3. Интерфейсы
- Есть узел `VID_04A9…PI_00` (класс USB, `usbprint`) и нет `MI_00` класса Image → **П1**. Лечить **первой**: остановить `stisvc`, disable/enable узла `PI_00`, `pnputil /scan-devices`, запустить `stisvc`. Даже если WIA-скан работает (П11) и даже если жалоба только на печать (П12).
- `MI_00` есть, но пакет `mfscn.inf` не под PID устройства → **П2** (проверить DriverStore; обычно хватает переэнумерации из П1).
- `MI_01` в problem 10 при здоровом родителе → **П6**.

### Уровень 4. Печать
- Очередь на `Microsoft IPP Class Driver` → **П3**: новая очередь на `Canon Generic Plus UFR II` (тот, что уже установлен), удалить IPP-очередь. Проверить, что выключен Windows Protected Print Mode.
- `Device Id` / `Device Path` порта ≠ живой `MI_01` → **П4**. Сверять **всегда**, нормальное описание порта ничего не доказывает.
- Ошибка `CnXP0PP.DLL`, `0x20` → **П5** (`winprint` / `RAW`), только при этой ошибке.
- Принтер по умолчанию — не USB-очередь аппарата; сетевые узлы (`SWD\IPP`, `SWD\ESCL`) чужого аппарата; очередь Canon на порту чужого устройства → **П14**.

### Уровень 5. Сканер Windows (WIA)
- Только сетевой сканер, `0x80210006` («устройство занято») → **П8** (+ проверить П1).
- Есть `SWD\EsclUsb\{…}`, нет `{6BDD1FC6-…}\NNNN` → **П11** = П1 без симптома.
- Проверять **реальным сканом в файл** (§10: у драйвера Canon элемент — через `InvokeMember`, `Transfer()` — без аргументов).

### Уровень 6. Программа Canon
- «Драйвер сканера, поддерживающий это ПО, не установлен» → не та программа для этого PID → **П9** (найти правильную по `CaddisUIPath` рабочего профиля ScanGear, §6).
- «Связь не установлена» при рабочем WIA → **П9**, **П8** (выбран профиль `… Network`) или **П13** (два профиля с `AvailableDriver = 1`, пустышка вроде `Canon MF Scan`).

### Профилактика (предложить, применять по согласию)
Запрет отключения USB Root Hub ради экономии энергии и USB selective suspend (§8). Кабель — в USB-B аппарата и в задний порт ПК без хаба.

### Финальная проверка (§4 шаг 6)
Реальный WIA-скан в файл; скан из той программы Canon, которой пользуется человек; тестовая страница **и лист глазами** (событие 307 с `0x0` бывает и у пустых листов через IPP); принтер по умолчанию = USB-очередь; полный цикл переподключения — всё должно подняться само.

## Если запущено из запускалки CanonFix.exe
Начальный промпт содержит выбранный симптом («сканер», «печать», «ничего не работает», свой текст) или режим «только диагностика». Симптом — подсказка, а не диагноз: всё равно пройти все уровни с шага 0. Рабочая папка и все файлы — `C:\fix`.

## Итоговый отчёт

В конце работы (а также при остановке на П7/П10 и в режиме «только диагностика») сохранить два файла:
`C:\fix\report_<ГГГГ-ММ-ДД_ЧЧММ>.md` и `C:\fix\report_<ГГГГ-ММ-ДД_ЧЧММ>.json`.

**Не включать:** серийные номера (в Instance ID заменять на `<SN>`), IP- и MAC-адреса, mDNS-имена, содержимое сканов. Имя ПК, build ОС, PID, `USBxxx`, `oemXX.inf`, версии драйверов и программ — можно.

**Markdown** — по образцу базы: ПК и ОС → PID и имя аппарата → что не работало → таблица проблем (номер, признак, подтверждена / исключена) → что сделано по шагам (команда → результат) → что осталось не тронуто и почему → как откатить → финальная проверка (лист глазами: да/нет) → открытые вопросы.
